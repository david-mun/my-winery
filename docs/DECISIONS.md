## 2026-11-03 구현 결정

- 영수증 무결성은 인증 사용자의 원시 DML 권한을 회수하고 `save_receipt`/`delete_receipt` RPC만 허용하는 방식으로 구현했다. 모든 항목·합계·소유권을 한 트랜잭션에서 검증한다. 수정 시 version을 요구한다. 일반 DB 사용자에게 직접 테이블 쓰기를 허용하는 지연 trigger 방식은 사용하지 않는다.
- 계정 변경은 단일 guard 행을 먼저 잠그며 역할/프로필/Auth 사용자 삭제에도 마지막 관리자 보호 trigger를 둔다. 다중 연결 동시성 실증은 실제 PostgreSQL 통합 검수로 남긴다.
- Auth 링크는 token_hash 템플릿과 서버 callback을 사용한다. 수락/복구 증명을 사용자·흐름·만료와 함께 서명한 HttpOnly 쿠키로 제한한다.
- 원본 스냅샷은 개인 서버 도구에서만 사용한다. 공개 demo에는 별도 가상 와인·가상 점수만 둔다. Vercel 업로드에서 원본 data/와 설계 문서/테스트를 제외한다.
- 서버 환경변수는 동적 조회로 읽어 빌드 시 개발/운영 주소가 고정되지 않도록 한다. 브라우저에는 Supabase client를 만들지 않는다.
- 이미지 선택은 10MiB/40MP까지 허용하고, 전송 전 2,000px/WebP·4MB 이하로 압축한다. 서버 재검증·재인코딩 후 저장한다. 원본 바이너리 보관은 MVP 범위에서 제외하며 사용자 원본 보관을 안내한다.
- Next.js 16.4.4와 lockfile을 사용한다. 이 환경의 Turbopack 포트 제한으로 dev/build는 Webpack을 사용한다.
- 로컬 PostgreSQL 엔진은 PGlite로 검증했다. E2E의 Auth/Storage는 로컬 어댑터이며 실제 SMTP·Supabase 서비스가 검증되었다고 보고하지 않는다.

## 2026-11-03 — 와인 목록을 모든 화면에서 한 열로 표시

사용자 제공 레퍼런스에 맞춰 여러 열의 타일을 한 줄에 한 와인이 들어가는 목록으로 변경했다. 실제 컬렉션과 공개 가상 데모는 같은 `WineList`를 사용한다. 사진/플레이스홀더는 항상 왼쪽, 이름·생산지·개인 구매 정보는 중앙, 외부 평점 기록과 최근 구매 단가는 오른쪽에 둔다. 좁은 화면에서는 평점·단가만 정보 아래로 이동하며 사진이 위쪽으로 넘어가지 않도록 한다. 평균 판매가 대신 기존 도메인의 최근 구매 단가를 표시하고 관측일·매칭 확인 상태·NULL 가격은 유지한다. 필터와 정렬 동작은 유지했다.

## 2026-11-14 — OCR 텍스트에서 확인 가능한 값만 구매 초안으로 옮김

새 구매 화면에서 번호가 붙은 한국어 POS 상품 목록을 로컬에서 해석한다. 바코드 뒤의 단가 × 수량 = 줄 금액이 명확한 품목만 금액과 수량을 채운다. 떨어진 가격은 후보로만 표시하고, 와인 연결·묶음 구성과 원본 대조는 사용자가 한다. 할인은 영수증 단위로 한 번 적용한다. 같은 구매일·결제액의 기존 영수증이 있으면 확인 링크를 제공한다. 붙여넣은 원문 전체나 카드승인 정보는 저장 요청에 넣지 않는다. CLOVA 도메인·API 키 없이 작동하며 이미지 인식 API를 호출하지 않는다.

## 2026-11-14 — 외부 와인명 검색과 원문 보존

구매 폼에서 사용자가 검색할 때만 Eclavin 한국 수입 와인 DB의 공개 검색 API(https://www.eclavin.com/api/wines)에 상품명 검색어를 보낸다. 네트워크 요청에 영수증 원문·구매 내역·개인 셀러 데이터를 포함하지 않는다. 공개 API는 후보를 찾는 용도다. 매장 접두어·용량·끝의 빈티지 표기를 검색할 때만 정리한다. 완전한 응답에서 정규화 이름이 하나로 일치할 때만 연결하고, 그 밖에는 후보를 선택하거나 원문으로 저장한다. API 사진·가격·평점은 가져와 저장하지 않는다. 번호와 상품명 자체가 같은 와인을 보장하지 않으므로 일치 결과도 되돌릴 수 있다.

공개 검색은 개인 DB를 검색하지 않는다. 최종 저장 시 새 영수증과 와인 연결을 단일 DB 트랜잭션으로 처리하며, 동일한 개인 와인은 재사용한다. 검색 장애나 결과 없음이 구매 입력을 막지 않는다.

## 2026-11-14 — 자동 후보 검색 및 사진 입력

상품명이 두 글자 이상이고 입력이 0.5초 멈췄을 때만 외부 와인 검색을 시작한다. 진행 중인 요청의 오래된 응답은 버린다. 다수 OCR 품목은 브라우저에서 동시 요청 두 건까지 처리한다. 영수증 전체 이미지는 Tesseract 한국어·영어 모델로 기기에서 인식하며 모델·워커도 앱과 같은 origin에서 제공한다. 사진 분석이나 선택만으로 구매를 저장하지 않는다.

개인 병 사진은 기존 비공개 업로드 경로를 사용한다. 공개 사진을 쓰려면 와인별로 Wikimedia Commons 후보를 직접 선택해야 한다. 사용 조건이 명시된 CC0 또는 CC BY 사진만 제공하고, 서버가 Commons 페이지 ID로 출처·라이선스·이미지 호스트를 다시 검증한다. 사진 및 작가/출처/라이선스 메타데이터를 보관한다. Eclavin 사이트 자체 사용 허용만 표기한 이미지는 재사용하지 않는다. 구매 트랜잭션이 반환한 병 순서별 소유자 와인 ID에만 사진 첨부를 진행한다. 첨부 일부가 실패해도 구매는 중복 저장하지 않으며 상세에서 실패를 알린다.

## 최초 관리자 인수와 메일 설정

최초 관리자는 지정된 이메일로 생성하고 서버에서 발급한 일회용 복구 링크로 본인이 비밀번호를 정한다. 로컬 인수 파일은 Git·배포 대상에서 제외하며 개발 서버의 인증 콜백 요청 로그도 생략한다. 비밀번호 설정 권한은 서버에서 검증한 초대 또는 복구 토큰에만 부여한다. 원격 대시보드에서 사용자 지정 SMTP를 설정해야 초대·복구 메일 본문을 변경할 수 있으므로 실제 메일 수신은 별도 검수한다.

## 개인 평점과 최소 평점 검색

새 개인 평점은 1.0~5.0점에서 0.1점 단위로 검증한다. 기존 0.5점 기록이 있으면 그대로 보관하며 해당 노트를 수정할 때 새 범위를 적용한다. 각 최소 평점 필터의 ‘전체’는 평점 없는 와인까지 포함하고, 숫자를 지정하면 해당 점수가 있는 와인만 대상으로 한다.

## 2026-11-17 — 모바일 사진 압축 호환성

Canvas의 WebP 요청이 PNG로 반환되거나 결과가 없으면 JPEG로 재압축한다. 반환 MIME과 파일 확장자를 일치시키고 투명 영역은 흰색으로 채운다. 4,000,000바이트보다 큰 결과는 품질(0.85/0.72/0.6), 이후 해상도를 단계적으로 줄여 재시도한다. 최초 긴 변 2000px, 원본 10MB·40MP 제한과 서버 검증/EXIF 제거는 유지한다. Bitmap과 canvas 메모리는 성공·실패 모두 해제한다.
