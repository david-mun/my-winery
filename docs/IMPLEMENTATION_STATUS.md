# 구현 진행 상태

마지막 갱신: 2026-11-17

## 현재 상태

원격 Supabase에 마이그레이션 6개를 적용하고 첫 관리자의 비공개 컬렉션을 이관했다. 공개 가입 차단, 구매 금액, 소유자 격리, 비공개 사진의 서명 조회를 실제 서비스에서 확인했다. 자동 검사 결과는 [검증 보고서](TEST_REPORT.md)에 기록했다.

`data/` 원본 스냅샷과 SQL 설계 초안은 보존했다. 실제 사진은 제공되지 않아 이미지 이관은 0건이다. 보유 병수는 구매 병수와 구분해 미확인으로 표시한다. Vivino 관측일 및 URL 검증 필요 상태를 보존하며 라이브 평점이라고 표시하지 않는다.

## 실제 환경 상태와 남은 작업

- 원격 Auth 회원 등록과 관리자 역할 부여를 완료했다. 운영자용 일회성 링크는 권한 0600의 로컬 파일로 전달한다. 사용자가 첫 비밀번호를 정한다.
- 원격 Auth 설정 조회에서 `disable_signup=true`를 확인했다. 실제 초대·재설정 메일 전달에는 사용자 지정 SMTP 및 메일 템플릿 구성이 남았다.
- 네이티브 PostgreSQL의 다중 연결 경쟁 조건, 원격 소유자 RLS와 private Storage를 검증했다. 로컬 화면은 `npm run dev` 후 `/login`에서 접근한다. `/demo`는 가상 데이터다.
- Vercel 운영 주소는 https://my-winery.vercel.app 이다. 배포 후 운영 도메인에서 로그인, 구매 조회, 관리자 접근을 검증했다. 외부 메일 수신 및 iOS·Android 실기기 설치는 미검증이다.

## 2026-11-14 — 공개 와인 DB 검색

구매 추가·수정 및 데모에서 Eclavin 공개 API로 상품명을 검색한다. 고유 이름 일치는 연결하고, 유사 후보는 사용자가 선택하며, 선택 생략·취소·장애 시 영수증 상품명을 사용한다. 빈 개인 컬렉션에서도 구매를 시작할 수 있다. 기존 와인에서 진입하거나 기존 구매를 편집하면 원래 연결을 유지한다. 원문과 선택명은 별도로 관리하며 검색만으로 DB를 변경하지 않는다.

로컬 단위·DB 30개와 화면 테스트 32개 통과. lint·타입 검사·프로덕션 빌드 통과. 예시 상품명 ‘클라우디 베이’로 로컬 데모 서버를 통한 실제 외부 검색 결과 7개 반환을 확인했다. 외부 사이트의 범위·정확성·가용성은 보장하지 않는다. 원격 DB에는 새 마이그레이션을 적용하지 않았다. 운영 저장 전 SETUP의 다섯 번째 마이그레이션까지 적용해야 한다.

## 2026-11-14 — 사진, 자동 검색 및 마이그레이션 실행 준비

모바일 촬영/사진 선택/수정 가능한 기기 OCR, 자동 와인 검색, 후보 미선택 시 영수증명 저장, 비공개 영수증·병 사진 첨부, CC0/CC BY 검색·출처 표시를 구현했다. DB migration은 총 6개다. 실제 PostgreSQL 18 임시 서버에서 최초 적용 → 재실행(대기 0) → 권한/버킷/함수 검증과 두 세션 동시 관리자 변경·영수증 수정 테스트를 통과했다. 이 로컬 엔진의 Auth/Storage 시스템 테이블은 테스트용이다. 실제 Supabase 적용은 앱 키가 아닌 SQL 연결 권한이 필요하다.

### 원격 적용 결과 — 2026-11-14

설정한 Supabase 프로젝트에 공식 CA를 사용한 TLS 세션 풀러 연결과 인증 성공. 읽기 전용 사전 점검에서 기존 이력 0건, 적용 예정 6건, 대상 충돌 없음. 6개 SQL을 단일 트랜잭션으로 적용한 뒤 종료하고 새 DB 연결에서 기록 6건·대기 0건을 확인했다. 공개 앱 테이블 RLS, private bucket과 Storage 정책, 사진 출처 필드, 마지막 관리자 보호 trigger, 구매 RPC 및 권한 제한 검증 통과. 앱 Data API의 0행 요청도 HTTP 200. 초기 관리자 등록·실제 영수증/사진 업로드·메일 발송·배포는 수행하지 않았다. 위의 ‘대기’ 표시는 작업 당시 기록이다.

### 사진 삭제

와인·영수증 상세와 구매 내역의 병 사진에서 사진 옆의 삭제 확인 또는 취소를 선택할 수 있다. 병 사진은 와인에 연결되어 있어서 같은 와인을 보여주는 구매 내역에도 삭제 결과가 반영된다. 네 화면 크기에서 취소, 삭제, 삭제한 주소의 404 응답 및 구매 내역 갱신을 검증했다.

가로형 목록의 왼쪽 사진 칸을 넓히고 사진을 카드 경계까지 채웠다. 목록에서는 사진 중앙을 기준으로 비율을 유지하며 잘라 표시한다.

와인 상세 상단에는 가장 최근 등록한 사진을 원본 비율로 맞춰 병 전체를 보여준다. 등록된 사진이 없으면 와인 종류에 맞는 기본 병 그림을 표시한다.

와인 목록은 내 평점 아래에 해당 와인의 가장 최근 작성된 후기 본문을 두 줄까지 표시한다. 평점만 입력한 노트는 미리보기에서 건너뛴다.

와인 목록에서 내 평점 숫자와 Vivino 숫자를 같은 크기로 표시하고, 국가명 옆에 국기를 표시한다. 두 최소 평점 슬라이더는 각각 1.0~5.0점에서 0.1점씩 조절하며 기본값은 전체다. 정렬은 선택 즉시 현재 검색 결과에 적용한다.

와인 목록 카드에서 내 평점 아래에 Vivino 평점과 확인일을 표시하고, 구매 횟수·병 수는 최근 구매 단가와 한 줄에 배치한다.

## 2026-11-17 — 실제 이미지 Gemini API 테스트

사용자 제공 영수증·여러 병 사진·단일 병 crop으로 실제 키를 사용해 테스트했다. 영수증은 식별정보를 가려 전송했다. 2.5 Flash-Lite는 목록 조회에 나타나지만 실제 분석은 신규 사용자 404였다. 3.5 Flash-Lite와 3.1 Flash-Lite에서 실제 이미지 JSON을 받았다. 호출용 스키마 복잡도 제한과 503도 확인했다.

상세 결과와 검증 한계는 [실제 이미지 테스트 기록](GEMINI_API_TEST_2026-11-17.md)에 남겼다. 개인 이미지·JSON 원문·일회성 실행기는 로컬 임시 폴더에만 보관했다. 앱 연동·DB 저장·배포는 수행하지 않았다.

## 2026-11-17 — 모바일 사진 압축 오류 수정

- `lib/image-client.ts`에서 WebP 미지원 시 PNG가 반환되어 용량 오류가 발생하는 경로를 JPEG 대체 인코딩으로 수정했다. 초과 용량은 품질과 해상도를 단계적으로 줄여 재시도한다. 와인·구매 병 사진·영수증 입력 모두 같은 함수를 사용한다.
- 실제 Playwright WebKit 27.2에서 고밀도 사진 7,186,532바이트로 기존 오류를 재현했고 수정 후 JPEG 2,475,104바이트, 2000×1333px로 성공했다. Chromium에서는 4,948,802바이트 사진이 WebP 1,588,646바이트로 성공했다. 실제 휴대폰 촬영·운영 DB 업로드는 미검증이다.
- `npm run lint`, `npm run typecheck`, `npm test` 39개(압축 회귀 6개 포함), `npm run build`, `git diff --check` 통과. 첫 build는 기존 Next.js 16.4.4 보안 경고로 중단됐고 같은 명령 재실행은 경고와 함께 성공했다. 의존성 보안 업데이트는 이번 수정에 포함하지 않았다.
- 사용자 승인에 따라 이 수정과 회귀 테스트만 main에 반영하여 Vercel 운영 배포한다. Gemini 설계와 실험은 포함하지 않는다.
