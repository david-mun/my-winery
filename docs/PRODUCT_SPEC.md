상태: 구현 전 계약 · 2026-10-25. 원본 요구는 [architecture.md](architecture.md), 새 기본값의 근거는 [DECISIONS.md](DECISIONS.md)를 참조한다.

2026-11-15 확장 설계: 영수증 사진과 와인 앞·뒤 라벨 사진을 Gemini로 분석하여 확인용 초안을 만드는 흐름을 추가한다. 상세/JSON 계약은 [GEMINI_PHOTO_ANALYSIS.md](GEMINI_PHOTO_ANALYSIS.md)를 따른다. 아래 MVP 범위는 최초 계획의 구분이며, 실제 구현 여부는 [진행 상태](IMPLEMENTATION_STATUS.md)가 기준이다.

## 1. MVP 범위

초대된 소수 사용자(목표 10명 이하)가 자신의 와인·구매·시음을 관리한다. 관리자는 계정만 관리하며 다른 사람의 구매 자료를 보지 못한다. 제품명은 My Wine List, 로컬 폴더명은 my-winery다.

| MVP 필수 | 후속 범위 |
|---|---|
| 초대 수락, 이메일/비밀번호 로그인, 재설정, 로그아웃 | 소셜 로그인, 공개 회원가입 제외 |
| 개인 와인 등록·수정·목록·상세, 검색·필터·정렬 | 다음 확장: Gemini 영수증·라벨 사진 분석; 공유 셀러는 별도 후속 |
| 영수증 및 개별/묶음 구매 CRUD, 금액 대조 | 환불·다중통화·자동 할인 배분 |
| 개인 평점·후기 CRUD, 과거 외부 평점 표시 | 외부 평점 자동 동기화 |
| 비공개 와인/영수증 이미지 업로드·조회·삭제 | HEIC 변환, PDF, 사진 편집, 후기 사진 |
| 관리자 초대·재발송·비활성화·재활성화·역할 변경·감사 조회 | 영구 삭제 자동화(출시 전 정책 결정 필요) |
| 반응형, PWA manifest·아이콘·홈 화면 실행 확인 | 오프라인 개인 데이터 조회·수정 |
| 스냅샷 dry-run/apply/verify 및 보안 테스트 | 통계 대시보드, 사용자 CSV/JSON 내보내기 |

기본 사진 업로드와 설치 메타데이터는 MVP에 포함한다. 신규 기능이 미구현인 경우 비어 있는 메뉴나 성공하는 척하는 버튼을 노출하지 않는다. 구매 내역과 별개인 재고 차감 모델은 아직 없다. **“누적 구매 12병 / 현재 보유 미확인”**으로 표시하고, 시음 후기를 써도 수량을 자동 차감하지 않는다.

## 2. 화면·상태 계약

| 경로 | 기본 동작 | 빈 값·실패·권한 |
|---|---|---|
| `/` | 인증·활성 상태에 따라 `/wines` 또는 `/login` 이동 | 비활성 계정은 접근 제한 안내 |
| `/login` | 이메일/비밀번호, 재설정 요청 | 재설정은 계정 존재 여부를 노출하지 않는 동일 안내 |
| `/auth/callback` | 인증 코드를 검증하고 허용된 내부 경로로 이동 | 만료·재사용 링크는 재발송 안내, 외부 return URL 거부 |
| `/welcome` | 유효한 초대 세션으로 비밀번호 설정 | 완료 전 개인 화면 접근 불가 |
| `/reset-password` | 복구 세션 검증 후 새 비밀번호 저장 | 일반 방문만으로 비밀번호 변경 불가 |
| `/wines` | 사용자별 통합 카드, 검색·필터·정렬 | 첫 사용: 와인 등록; 검색 0건: 필터 초기화 |
| `/wines/new`, `/wines/[id]` | 등록, 상세에서 편집·구매·후기 연결 | 타인/없는 ID는 같은 404; 중복 후보는 기존 와인 선택 |
| `/purchases`, `/purchases/new`, `/purchases/[id]` | 영수증 목록·등록·상세 편집 | 합계 불일치 시 저장 차단; 실패 시 입력 유지 |
| `/reviews` | 내 후기 목록; 작성·편집은 와인 상세에서도 가능 | 점수 또는 본문 중 하나 이상 필요 |
| `/settings` | 자기 계정 정보·로그아웃 | 권한 변경 기능 없음 |
| `/admin`, `/admin/users`, `/admin/users/[id]` | 사용자 계정/초대/역할/상태/감사 이력 | 일반 사용자 서버 접근 거부, 콘텐츠 링크 없음 |

로그인으로 되돌아갈 때 안전한 내부 경로만 보존한다. 모든 폼은 저장 중 중복 제출을 막고 성공/오류를 텍스트로 알린다. 세션 만료 시 입력 보존을 안내하되 개인 정보를 영구 브라우저 저장소에 자동 기록하지 않는다.

## 3. 와인 목록과 집계

- 같은 소유자의 같은 와인은 빈티지가 달라도 카드 하나다. 이름만 비슷한 다른 생산자의 와인을 자동 병합하지 않는다.
- 검색 대상: 한글명·원어명·생산자·국가·지역·품종. 앞뒤 공백을 제거하고 대소문자를 무시한다.
- MVP 필터: 종류, 국가/지역, Vivino 최소 점수, 내 최소 점수. 같은 종류 그룹의 복수 선택은 OR, 서로 다른 필터는 AND다. 빈티지·가격 범위·구매처 필터는 후속으로 둔다.
- URL에 검색·필터·정렬을 기록한다. 알 수 없는 필터값은 기본값으로 정규화한다. 뒤로 가기로 복원한다.
- 정렬: 최근 구매일 내림차순(기본), 이름, Vivino 점수, 내 점수, 최근 단가 오름/내림차순. NULL은 항상 마지막, 동률은 이름과 ID로 고정한다.
- 구매 횟수는 해당 와인이 연결된 **서로 다른 영수증 수**, 구매 병 수는 연결 항목의 `bottle_quantity` 합이다.
- 최근 단가는 가장 최근 구매의 개별 와인 항목에 명시된 단가다. 그 구매가 미배분 세트이면 `가격 미확인`으로 표시한다. 이전에 확인된 가격을 보조로 보여줄 때는 날짜를 붙인다.
- 결제 지출은 영수증 `paid_amount` 합으로 계산한다. 와인 연결 조인으로 영수증 결제액을 중복 합산하지 않는다.

### 대표 평점 결정(제안 기본값)

내 평점은 `created_at DESC, id DESC` 순 최신 후기의 점수다. 최신 후기가 글만 있으면 `평점 없음`이다. 후기 수정은 생성 순서를 바꾸지 않는다. 이관 시 시음일을 생성일로 추정하지 않는다.

외부 평점은 확인일 최신 순, 같은 날이면 `ALL_VINTAGES` 우선, 이후 원본 행 번호가 작은 순으로 대표를 정한다. 수동 입력 동률은 생성시각·ID로 고정한다. 상세에는 모든 범위별 관측을 보여준다. 점수 옆에 `2026-10-11 확인 · 전체 빈티지/2025/NV`와 검증 상태를 함께 표시한다. 매칭 확인 필요 관측은 배지를 붙여 보존하되 Vivino 4.0+ 필터·평점순 정렬의 유효 점수에서는 제외한다. 점수 없는 항목도 최소평점 필터에서 제외한다.

초기 기대: 카드 10개, 러시안 잭·조지 미쉘 각각 2회/2병. 위 대표 규칙의 Vivino 4.0+는 7개, 내 평점 4.0+는 2개다.

## 4. 입력·수정·삭제

| 대상 | 입력/검증 계약 |
|---|---|
| 와인 | 이름 필수(1~200자), 유형 enum, 나머지 모르면 NULL; 생산자·국가 임의 추론 금지 |
| 구매 | 구매일·실결제액·1개 이상 상품/묶음 항목 필수. KRW 정수, 음수 결제·할인 금지 |
| 일반 항목 | 한 와인·빈티지·양의 정수 병 수, 줄 전체 금액. 단가×병 수와 줄 금액 검증 |
| 묶음 항목 | 묶음 전체 금액과 구성 병 목록. MVP 병별 배분은 NULL |
| 빈티지 | 4자리 연도(1000~2999), NV, UNKNOWN. 미입력은 UNKNOWN |
| 후기 | 1.0~5.0점/0.1 간격 또는 점수 없음, 본문 최대 5,000자, 시음일 선택 |
| 외부 URL | URL 파서로 HTTPS와 정확한 Vivino 허용 호스트 검사; URL의 인증정보 금지 |
| 파일 | JPEG/PNG/WebP, 최대 10MiB, 서버에서 실제 포맷 검사·디코딩·EXIF 제거 |

영수증 편집은 전체 항목과 집계를 한 트랜잭션으로 저장한다. 원본 구매일은 DATE, 생성·수정 시각은 timestamptz로 구분한다. 미래 구매일·시음일은 사용자 입력 오류로 안내하는 기본값을 사용한다.

영수증 삭제는 날짜·결제액·연결 구매 수를 보여주고 확인을 받는다. 해당 영수증과 항목을 삭제하되 와인 마스터·독립 후기는 유지한다. 연결 구매가 있는 와인은 삭제를 거부하고 구매 정리를 안내한다. 구매가 없는 와인의 후기·이미지 삭제 영향은 확인 화면에 명시한다. 수정 이력의 영구 버전 관리는 후속 범위이며, MVP는 생성/수정 시각을 제공한다.

## 5. 반응형·접근성·PWA

360/390px는 단일 카드와 하단 탐색, 768px는 2열, 1440px는 필터 사이드바와 카드 그리드를 검수한다. 탭은 와인·구매·시음·설정으로 구성하고 관리자 메뉴는 권한 보유자에게만 표시한다. 라벨, 오류 연결, 키보드 포커스, 모달 포커스 복귀, 44px 이상 터치 영역을 보장한다.

이미지 없는 경우 자체 플레이스홀더와 대체 텍스트를 제공한다. 로딩·빈 목록·연결 실패·권한 거부를 구분한다. 설치용 manifest와 자체 아이콘, safe area, 홈 화면 실행을 검수한다. 개인 화면·API·서명 URL은 공유 캐시/서비스워커 캐시 대상에서 제외한다. 네트워크가 없으면 재연결 안내를 표시한다.

## 6. 사진으로 입력 (Gemini 후속 설계)

| 화면 | 추가 행동 | 저장 전 계약 |
|---|---|---|
| 구매 추가 | 영수증 1장 촬영/선택 → 미리보기·개인정보 가리기 → 명시적으로 분석 | 매장/날짜/상품 원문·와인 후보/병 수/세트/할인/실결제액 확인. 미확인·합계 불일치·처리 불가 품목은 저장 차단 |
| 와인 추가 | 한 병의 앞 라벨 + 선택적 뒤 라벨 1~2장 → 분석 | 사진에서 확인한 와인 상세와 AI 제안을 분리. 이름/종류 확인, 기존 자기 와인 중복 확인 후 저장 |
| 구매 품목 보완 | 선택한 품목의 병 라벨 분석 | 해당 와인 상세만 보완. 영수증의 날짜·가격·수량은 유지 |

분석은 저장하지 않는다. 기존 와인에 연결하면 카드가 늘지 않으며 상세는 자동 덮어쓰지 않는다. 와인 사진만으로 구매나 시음 기록을 생성하지 않는다. 분석 중 취소/사진 교체·늦은 응답·재분석이 수동 수정값을 덮어쓰지 않아야 한다.

관측값은 이름·생산자·종류·산지·품종·빈티지·도수·용량·라벨 설명과 근거 이미지/문구를 포함한다. 일반 지식으로 제안한 생산지·스타일·향·음식 조합·온도는 `AI 제안 · 확인 필요`로 표시하고 사용자가 채택하기 전에는 저장하지 않는다. 외부 평점·링크·개인 평점·시음일은 AI 생성 대상에서 제외한다.

키 미설정/한도 초과/판독 불가 시 실패 이유를 한국어로 표시하고 직접 입력·기기 OCR을 제공한다. 선택 이미지를 Google로 전송한다는 안내를 분석 버튼 전에 표시한다. 무료 모드의 영수증은 개인정보를 가린 결과만 보내며, 사진 저장 여부는 분석과 별도 선택이다. 구체적인 전송/응답/실패/저장 매핑은 [상세 계약](GEMINI_PHOTO_ANALYSIS.md)을 따른다.
