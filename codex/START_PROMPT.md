# Codex 최초 구현 프롬프트 — My Wine List

당신은 이 폴더를 작업 디렉터리로 사용하는 시니어 풀스택 엔지니어입니다. **계획만 작성하지 말고 파일을 실제로 생성하고 동작 가능한 첫 버전(MVP)을 구현**하세요.

## 1) 읽을 자료
- 루트의 `AGENTS.md`를 준수하세요.
- `docs/architecture.md`에서 핵심 제품 요구사항과 모바일/PC 와이어프레임, 사용자 역할, 이관/인수 기준을 확인하세요.
- `database/schema_design_v1.sql`은 검증 전 설계 초안입니다. 무조건 실행하지 말고 PostgreSQL/Supabase 보안·정합성 검토 후 버전형 SQL 마이그레이션으로 작성하세요.
- `data/wine_purchase_rows.csv`, `data/receipt_totals.csv`, `data/source_manifest.json`은 실제 Google Sheets에서 내보낸 원본 스냅샷입니다.

## 2) 구현할 제품
- 프로젝트명: My Wine List
- Next.js App Router + TypeScript + Tailwind CSS + shadcn/ui, Supabase Auth + PostgreSQL + Storage, Vercel 배포 준비.
- iPhone/Android/PC에 대응하는 모바일 우선 웹 UI; 홈 화면 설치 가능한 PWA 메타데이터 포함.
- UI는 https://www.vivino.com/en/explore/grapes/cabernet-sauvignon 의 이미지 중심 와인 카드, 검색·필터·평점 표시 방식에서 영감을 얻되 사이트 디자인·이미지·텍스트를 복제하지 마세요. 한국어 우선, 와인 사진 없는 경우 세련된 플레이스홀더 제공.
- 초대 기반 이메일 로그인/로그아웃/비밀번호 재설정, 비로그인 접근 차단.
- 와인 목록: 같은 와인 통합 카드, 정렬, 와인명 검색, 종류/생산지/Vivino 4.0+ 필터, 내 평점·보유/구매 정보.
- 와인 상세: 구매 횟수, 각 구매일/가격/빈티지/영수증, Vivino 링크(외부 이동), 개인 점수·후기 CRUD.
- 구매: 영수증/개별/묶음 항목 구조, 영수증 이미지 업로드 및 비공개 조회, 금액 보존.
- 관리자 `/admin`: 사용자 이메일 초대, 회원 상태 확인, 비활성화, 역할 변경, 안전한 삭제 흐름, 관리자 작업 감사 로그. 일반 사용자는 UI 우회/API 직접 호출 모두 거부. 마지막 admin 삭제 금지.
- 가입자마다 완전한 독립 데이터. 운영자는 다른 사용자의 비공개 와인·시음 내용을 기본으로 열람할 수 없어야 합니다.

## 3) Supabase와 데이터 이관
- 공개 테이블 모두 적절한 RLS와 테스트, 소유자 일치 FK, 안전한 인증/관리 API 구축.
- Storage 비공개 버킷(예: `wine-assets`)에 와인 사진과 영수증 저장. DB에는 object path 및 MIME 저장. 원본 사진 파일은 현재 묶음에 없으므로 임의 다운로드/생성해서 이관 완료로 보고하지 마세요.
- `data/` 스냅샷을 입력으로 최초 관리자 계정 소유의 마이그레이션/seed 스크립트 구현. 미설정 시에는 안전한 dry-run 가능하게 만들고, 실제 쓰기는 명시적 실행 옵션이 있어야 합니다.
- 검증 기준: 서로 다른 와인 10종, 구매 와인 12병, 영수증 2건, 결제액 143,500원 + 150,400원 = 293,900원.
- 2026-09-13 세트 39,900원은 러시안 잭·조지 미쉘 두 병이 공유하는 하나의 묶음 항목. 각각 39,900원씩 배분하지 말고 병별 금액 NULL.
- 2026-10-10 쿠폰 18,000원은 영수증 레벨 할인으로 유지. `NV`와 `UNKNOWN` 구분. Vivino 2026-10-11 평점은 기준일 포함 기록하되 라이브값으로 표시하지 마세요.
- 조지 미쉘과 Golden Mile 간 URL 매칭은 검증 필요 상태로 표시하세요.
- 이관 반복 실행 시 중복 생성하지 말고 명확한 정합성 검사와 오류 보고를 제공하세요.

## 4) 작업 방식
1. 현재 저장소를 확인하고 간단한 구현 계획을 작성한 후 즉시 로컬 파일 구현에 들어가세요.
2. 아래 순서로 작동하는 수직 슬라이스를 완성하세요: Next.js 부트스트랩 -> DB/클라이언트 구성 -> Auth/RLS -> 목록·상세 -> 구매/후기 -> Admin -> 데이터 이관 -> PWA/반응형 -> 테스트/문서.
3. Supabase 키가 없다면 `.env.example`, 설정 가이드, mock/demo용 선택적 UI 또는 데이터 검증 dry-run을 제공하되 작동하지 않는 DB 연결을 작동한다고 보고하지 마세요.
4. `.gitignore`, README, 마이그레이션, 테스트를 작성하세요. `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` 등 실제 제공한 명령을 가능한 한 실행하세요.
5. 외부 계정 생성·비밀키 등록·실제 데이터 업로드·GitHub push·Vercel 배포·프로덕션 DB 변경은 사용자 승인 없이는 수행하지 마세요. 연결이 필요하면 로컬 코드까지 완성하고 정확히 필요한 설정 목록을 작성하세요.
6. 작업 완료 시 변경 파일, 구현 기능, 테스트 결과, 차단된 단계, 다음 수행 명령을 한국어로 요약하세요. 필요할 때만 질문하고 사소한 미정사항은 안전한 기본값을 사용하세요.

**중요:** 이 작업은 기존 문서를 단순 요약하는 작업이 아니라 실제 실행 가능한 웹앱 소스코드를 작성하는 개발 작업입니다.
